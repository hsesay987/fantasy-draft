# Name Place Animal Thing (NPAT) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship NPAT, a letter-and-categories party game with rarity scoring, in party rooms (phones, screen host, teams, tournaments) and as a solo daily.

**Architecture:** A pure engine `app/topicDraft/formats/npat.ts` owns rounds, letters, answers, the unknown-answer vote, tiers and scoring. Accepted-answer lists are data behind a registry (`npat/source.ts`, like `pecking/source.ts`) so room bundles never carry answers. A server-only history overlay (`npat/history.ts`, fed from a new `NpatAnswer` table) moves tiers down or to Too Obvious; the engine reads it through the same registry pattern, so tests run without a database.

**Tech Stack:** Next.js 16 + React 19 web, Express 5 + Socket.IO backend with in-memory rooms, Prisma + Postgres (one new table), Vitest.

**Spec:** `docs/superpowers/specs/2026-11-13-new-games-design.md`, section 3 and "Shared rules".

## Global Constraints

- Format id `"npat"`, title "Name Place Animal Thing". Joins `PARTY_FORMATS` and the server's `FORMAT_IDS`. 2+ players.
- Categories: Classic (Name, Place, Animal, Thing, the default), topic sets (Superhero, Footballer, Film, Food, Country, Pokémon and so on), Custom (host picks 4 to 6 from the full list). About 12 categories at launch, each with its own accepted-answer list.
- Round: a random letter. Hard letters (Q, X, Z, Y and similar) are left out unless the host turns on "Hard letters". A letter is drawn only when every chosen category has at least 15 accepted answers for it. One answer per category.
- Timer: 60 s default; host chooses 45, 60 or 90 s. The round ends early when every player has filled every category, or when "First to finish stops the clock" is on and someone finishes.
- Validity: answers are normalised (case, accents, "the", stored aliases). An answer that does not start with the letter is rejected automatically (0). An answer not on the list goes to a room vote at the reveal: majority accepts, a tie accepts. The vote needs at least 3 voters besides the answerer; with fewer, the answer is accepted. Accepted unknown answers are saved for review and never added to the lists automatically.
- Tiers (our own names, exact points): Common 10, Too Obvious 15, Solid 30, Rare 60, Deep Cut 85, Unicorn 100.
- Base tier = percentile band of familiarity within each category, so every category spreads across tiers (band edges set by the builder).
- History: only changes a tier once the category has at least 30 recorded plays. An answer players give often moves down a tier. Too Obvious applies when the base tier is Rare or higher and the answer appears in at least 5% of that category's plays. Counts update only from finished rooms and dailies; one player adds at most 1 per answer per day. Table `NpatAnswer { category, answer, count, updatedAt }` via a Prisma migration; no admin page.
- Same answer as someone else in the room: each player who gave it gets half the tier's points, rounded up. Teammates with the same answer are not docked; their team scores it once. Invalid or blank: 0.
- Teams sum their members. Tournament slots map their topic to a category-set id. Awards ranked by game points, ties share a place.
- Solo daily: one letter, four categories, same for everyone, seeded by date; unknown answer scores 0 and is saved for review; shareable result; Trivia hub tile in the HubArt style.
- Hidden information: nobody sees other players' answers until the reveal (also not a seat with no token, and not the screen).
- Room screens (`app/play/views/*`, `app/room/*`, everything reachable from them) must never import `app/topicDraft/npat/data/*` or `app/topicDraft/npat/lists.ts`. A static import-graph test enforces it.
- Drinking mode optional: 1 sip to a player whose answer was voted out or rejected for the letter. Nobody else sips.
- Layout works at 320px with 12 seats. All copy and lists are our own; familiarity data must carry a free, open licence.
- Commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Never use `backend/.env.local` or the `api-local` config. Local API uses `DATABASE_URL=postgresql://localhost:5432/toppic_dev`. Never `pkill -f`.

## Rulings made while planning

- **Data location.** Lists live in `app/topicDraft/npat/data/` (only `app/topicDraft` syncs to the backend, and the server scores). Cost if wrong: one folder move.
- **Rounds.** The spec does not say how many rounds: host sets 1 to 8, default 3 (stored in `opts.npatRounds`). Cost if wrong: one constant.
- **Phases.** `write` (timer), then per category `reveal` (answers flip together, tier badges, groups), with a `vote` sub-phase of `VOTE_MS = 8_000` only when an unknown answer exists, `REVEAL_MS = 6_000` per category; then a round summary; host can skip a reveal.
- **History in tests.** The engine reads tiers through `tierOf(category, answer)` from `npat/source.ts`; `npat/history.ts` wraps it with the DB overlay on the server only. Solo and daily use base tiers plus the overlay the API returns with the daily.
- **Review queue.** Unknown accepted answers and daily unknowns are saved as `NpatAnswer` rows with `category = "review:<category>"`, so no second table is needed. They never feed tiers. Cost if wrong: filter these rows out later.
- **Rematch.** Avoids letters already played in this room (`room.seen` keys `np:<letter>`).
- **Departures.** A player leaving mid-round counts as having answered blanks; the round never stalls.

## Review Focus

1. Accent, case and "the" variants of the same answer (`Éclair`/`eclair`, `The Hulk`/`hulk`) group as one answer and are both docked; a different spelling that is an alias of it also groups. Test in Tasks 1 and 4.
2. An answer starting with the letter only after normalisation (leading "the", accent: letter `E`, answer `Éclair`; letter `H`, answer `The Hulk`): decide by the normalised text, and accept both. Test in Task 1.
3. Fewer than 3 voters (2 players, or everyone else left): the unknown answer is accepted without a vote. Test in Task 4.
4. A seat with no token or another seat during `write` never sees any answer; only after the category's reveal. Test in Tasks 4 and 6.
5. Same player adds one answer 20 times in a day to history, or a tournament replays the same round: the count rises by 1 only. Test in Task 3.

**Interfaces:**

### Task 4: Engine

**Files:**

- Test: `app/topicDraft/formats/npat.test.ts`

**Interfaces:**

- Produces:

  - `type NPState = { players: string[]; teams: string[][] | null; categories: string[]; rounds: number; round: number; letter: string; phase: "write" | "reveal" | "vote" | "summary"; cat: number; answers: Record<string, string[]>; submitted: string[]; stopEarly: boolean; roundMs: number; hard: boolean; history: NPRound[]; points: Record<string, number>; teamPoints: number[]; phaseAt: number; startedAt: number; done: boolean; seed: number; drinks?: DrinkState }`
  - `type NPView` (state with `answers` for others hidden during `write` — each seat sees only its own; during reveal only categories up to and including `cat` appear in `history`; unknown votes visible only to voters until closed)
  - `init(o: { players; categories: string[]; rounds: number; roundSeconds?: 45|60|90; hard?: boolean; stopEarly?: boolean; teams: number; teamMap: Record<string, number>; avoid?: string[]; drinking?: boolean; seed: number; now: number }): NPState`
  - `answer(s, by, cat: number, text: unknown, now): NPState` (during `write`, text ≤ `ANSWER_MAX`, overwrites that player's answer for the category; out-of-range `cat` or non-string refused, state unchanged), `finish(s, by, now)` (player marks done; round ends early when all done or `stopEarly` and one done), `vote(s, by, ok: boolean, now)` (voters are everyone except the answerer, one vote per unknown answer, during `vote`), `next(s, now)` (host skip), `tick(s, now)`, `settle(s, gone: string[], now)`, `redactFor(s, me: string | null): NPView`, `seenKeys(s): string[]`, `winners(s): string[]`, `scoreCategory(...)` as an internal pure helper exported for tests: given the answers of a category it returns per-player `{ points, tier, shared }`.
